# Architecture Decision Records

Short documents recording a decision, the context that forced it, and the
consequences accepted along with it.

An ADR is written when a choice is **hard to reverse later** or when the
reasoning would otherwise be lost — so that a reviewer can point at it instead
of re-litigating the same question in a PR thread.

## Status values

- **Proposed** — written, not yet agreed
- **Accepted** — agreed and in force
- **Superseded** — replaced by a later ADR, which should link back

## Writing one

Number sequentially, name the file `NNNN-kebab-case-title.md`, and cover:
context, the decision, alternatives rejected and why, and the consequences —
including the costs being accepted, not only the benefits.
